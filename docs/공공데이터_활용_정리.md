# 공공데이터 활용 정리

돌봄바통이 쓰는 용인시 공공데이터의 출처, 가공 방법, 서비스 흐름, 한계를 정리한 문서다. 2026-11-14에 작성했다.

- 현재 상태(1~3장)는 레포의 코드와 시드, 이슈 #29·#30·#31, PR #73에서 확인한 사실만 적었다.
- 후보 데이터(4장)는 2026-11-14에 공공데이터포털 상세 페이지로 확인했다. API를 직접 호출해 본 것은 #29에 기록된 두 건뿐이다.

## 1. 요약

용인시 장애인복지시설 53곳과 공식 사업안내 기반 지원제도 5개를 DB에 넣어 두었다. 보호자가 단기·장기와 지역을 고르면, 대상자 나이에 맞는 제도와 그 제도에 연결된 유형의 시설을 같은 구부터 보여준다.

공공데이터 API를 실시간으로 부르지는 않는다. 용인시 API와 용인시청 시설현황을 사람이 맞춰 본 CSV를 관리자 API(ADMIN-01)로 적재하고, 사용자 요청 중에는 DB 값만 쓴다.

## 2. 지금 쓰는 데이터

### 2-1. 시설 53곳

| 항목 | 내용 |
|---|---|
| 원자료 1 | 공공데이터포털 [경기도 용인시_복지시설 정보 조회 서비스](https://www.data.go.kr/data/15097222/openapi.do) (용인시 제공). #29에서 호출을 확인했고 자동승인이며 252건이다. 필드는 구, 시설명, 주소, 전화뿐이고 시설 유형과 좌표는 없다. |
| 원자료 2 | [용인시청 장애인복지시설현황](https://www.yongin.go.kr/home/www/www18/www18_03/www18_03_08.jsp). 시설구분(복지관, 주간이용센터, 공동생활가정, 거주시설 등)이 있다. |
| 정리 방법 | 원자료 1의 252건 가운데 원자료 2와 이름·주소로 맞춰 유형을 붙일 수 있는 시설만 남겼다. 원자료 1에서 온 행은 `YONGIN_API` 42건, 원자료 2에만 있는 행은 `MANUAL` 11건이다. |
| 파일 | `src/main/resources/publicdata/facility_seed_yongin.csv`, 수집 시각 2026-11-08 |
| 적재 | `POST /api/v1/admin/public-data/sync`(ADMIN-01). `(source, external_id)` 기준 upsert |

구별로는 처인구 29곳, 기흥구 20곳, 수지구 4곳이다. 수지구 4곳은 정리 과정에서 빠진 것이 아니다. 시청 시설현황 페이지에도 수지구 소재는 수지장애인복지관(부설 주간이용센터 포함), 해오름의집, 지구촌보호작업장뿐이다. 2026-11-14에 페이지와 다시 대조했다. `수지장애인자립생활센터`는 이름과 달리 소재지가 기흥구라 기흥으로 들어가 있다.

유형별로는 공동생활가정 11곳, 거주시설 11곳, 주간이용센터 10곳, 직업재활시설 8곳, 장애아재활치료시설 5곳, 장애인복지관 3곳, 자립생활지원센터(IL) 3곳이 있다. 시각장애인등 생활지원센터와 수어통역센터는 1곳씩이다.

### 2-2. 지원제도 5개

기획이 공식 사업안내를 규칙표로 정리했고(#31), `R__seed_support_program.sql`로 넣는다.

| 제도 | 기간 | 나이 조건 | 근거 문서 |
|---|---|---|---|
| 발달장애인 긴급돌봄 | 단기 | 6세 이상 65세 미만 | 2026년 발달장애인 긴급돌봄서비스 사업안내 |
| 발달장애인 주간활동 | 장기 | 18세 이상 | 2026년 발달장애인 활동서비스 사업안내 |
| 장애인 활동지원 | 장기 | 6세 이상 (65세 이상도 결과에 포함, #84) | 장애인활동지원 공식 제도소개 |
| 발달장애인 가족휴식지원 | 단기 | 없음 | 2026년 발달장애인지원센터 사업안내 |
| 발달장애인 부모상담지원 | 장기 | 없음 | 보건복지부 발달장애인 부모상담지원 |

제도마다 공식 링크, 대상, 신청 절차가 들어 있다.

### 2-3. 제도와 시설 유형 연결

| 제도 | 연결되는 시설 유형 | 비고 |
|---|---|---|
| 주간활동 | 주간이용센터 | |
| 활동지원 | 자립생활지원센터(IL), 장애인복지관 | |

단기 제도에 시설을 연결하지 않은 것은 의도한 것이다. 2026-11-05 기획 결정이 "단기는 확인된 시설만 안내하고, 없으면 제도와 문의처를 안내"였다(#29).

## 3. 서비스에서 쓰이는 흐름 (RES-01·RES-02)

1. 보호자가 단기·장기, 필요한 날짜, 지역을 고른다. 지역을 비우면 대상자 등록 지역을 쓴다.
2. 기간과 대상자 나이(출생연도로 계산)에 맞는 제도를 Java 규칙으로 고른다. LLM은 쓰지 않는다.
3. 고른 제도에 연결된 유형의 시설을 검색 지역 구부터, 다음 다른 구 순서로 보여준다.
4. 추천 이유는 템플릿 문장이다. 시설은 "기흥구에 있는 주간이용센터예요.", 제도는 "장기 돌봄과 관련된 제도예요."처럼 나온다.
5. 모든 결과에 "실제 신청 자격과 이용 가능 여부는 해당 기관에 확인이 필요합니다."를 붙인다.

코드는 `ResourceService.search`(`src/main/java/com/batong/resource/service/ResourceService.java:49`)다.

## 4. 확인했지만 쓰지 않은 데이터와 추가 후보

### 4-1. 이미 확인하고 제외한 것 (#29, 2026-11-05)

- [경기도_장애인 단기거주시설 현황](https://www.data.go.kr/data/15058572/openapi.do): 경기도 30건 중 용인 0건. 그래서 긴급돌봄에 연결할 시설이 없다.
- [경기도_장애인복지시설(영유아,작업활동등) 현황](https://www.data.go.kr/data/15058729/openapi.do): 용인 1건(시각장애인시설)이라 대상이 아니었다.

## 5. 향후 확장 계획

아래는 MVP 이후 순서이고, 모두 기존 테이블(`facility`, `support_program`, `program_facility_type`)과 기존 적재 흐름(ADMIN-01) 안에서 할 수 있다.

| 순서 | 할 일 | 효과 | 비고 |
|---|---|---|---|
| 1 | 용인시 등록장애인 API로 구별 지적·자폐성 장애인 수 조회 | "왜 용인에서 시작하는가"의 근거를 원 통계로 보강한다 | 코드 변경 없이 키만 있으면 된다 |
| 2 | 활동지원 기관 현황에서 용인 행을 시설 CSV에 추가하고 활동지원 제도와 연결 | 장기 검색에서 실제로 신청할 수 있는 기관이 나온다. 좌표도 생긴다 | `facility_type` 값을 새로 정해야 한다 |
| 3 | 긴급돌봄·가족휴식에 신청처 안내 보강 | 단기 검색에서 시설 0건일 때도 연락할 곳이 생긴다 | 신청처는 지역발달장애인지원센터인데, 용인 센터의 공식 출처를 아직 찾지 못했다 |
| 4 | 지자체복지서비스 API로 용인시 장애인 관련 자체 사업 검색 | 제도 5개 외 용인 고유 사업을 후보로 올린다 | 규칙표로 넣을 사업을 정한다 |
| 5 | 기동 시 시설 테이블이 비어 있으면 자동 적재 | TRD 9-2와 맞춘다 | PR #73에서 테스트 영향 때문에 미뤘다 |

하지 않는 것도 적어 둔다. 지도 표시는 좌표가 없는 시설이 대부분이고, 지오코딩은 명세에 없는 외부 API라 넣지 않는다. 실시간 API 호출은 TRD가 사용자 요청 중 외부 호출을 막고 있어서 하지 않는다.

## 6. 현재 한계

| 한계 | 내용 |
|---|---|
| 최신성 | CSV 기준 2026-11-08. 갱신은 ADMIN-01을 수동으로 호출해야 한다. |
| 단기 시설 0건 | 긴급돌봄·가족휴식은 제도만 나오고 시설은 나오지 않는다. |
| 자료 간 불일치 6곳 | `needs_check=Y`. API와 시청 자료의 이름·주소·전화가 다르다. |
| 전화번호 없음 12곳 | 원자료에 없어 비웠다. |
| 좌표 없음 | 53곳 모두 위경도가 없어 거리순이 아니라 구 단위로 정렬한다. |
| 시설 링크 | 53곳 모두 시청 시설현황 페이지 하나로 연결된다. 시설별 홈페이지가 아니다. |
