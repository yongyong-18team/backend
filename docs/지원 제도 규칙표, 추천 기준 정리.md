# 지원 제도 규칙표, 추천 기준 정리

## 1. 무엇을

TRD·ERD·API 명세 v1.4를 기준으로, 기존에 선정한 지원제도 5개의 이용 조건·대상 연령·신청 절차·공식 근거자료를 정리했습니다.

또한 RES-02 조건 검색에 사용할 자동 추천 기준과 예외 처리 방향을 정의하고, 기존 용인시 시설 CSV 53건의 시설 유형 9개를 바탕으로 **제도별 관련 시설 유형 매핑 정책**을 수립했습니다.

### 작업 내용

- 기존 지원제도 5개 유지 및 공식 사업지침 조사
- 제도별 이용 대상·연령·신청 절차 정리
- 제도별 `program_type`, `care_term` 분류
- `target_conditions`에 반영할 기본 추천 조건 정의
- 용인 지역 적용 여부 및 공식 신청 경로 검토
- 실제 신청 자격과 서비스 내 추천 조건 구분
- 기존 시설 유형 9개 분석 및 제도별 관련 시설 매핑표 작성
- 시설 매핑 기준과 검색 결과 처리 정책 정리

## 3. 자동 추천 기준 (`target_conditions`)

### 3-1. 기본 정책

돌봄바통의 제도 추천은 **대상자의 연령과 돌봄 기간을 기준으로 1차 필터링**합니다.

현재 사용자 프로필에서 확인할 수 없는 장애 등록 여부·소득·긴급사유·서비스 중복 이용 여부 등은 자동으로 판단하지 않고, 상세 화면에서 안내합니다.

본 추천은 이용 가능한 제도를 탐색하기 위한 기능으로, 실제 지원 자격이나 서비스 이용 가능 여부를 확정하지 않습니다.

### 3-2. 제도별 자동 추천 조건

| 제도 | 연령 기준 | 돌봄 기간 | 추가 자격 확인 사항 |
| --- | --- | --- | --- |
| 긴급돌봄 | 6세 이상~65세 미만 | `SHORT` | 장애 등록 여부, 긴급 이용 사유, 제외 조건 |
| 주간활동 | 18세 이상 | `LONG` | 장애 유형, 취업 여부, 다른 서비스 이용 여부 |
| 활동지원 | 기본 6세 이상~65세 미만 | `LONG` | 65세 이상 예외, 장애 등록, 종합조사 및 자격심의 |
| 가족휴식지원 | 자동 연령 제한 없음 | `SHORT` | 가족관계, 장애 등록 여부, 수행기관 모집 여부 |
| 부모상담지원 | 자동 연령 제한 없음 | `LONG` | 부모·보호자 자격, 자녀 장애 등록, 영유아 예외 |

### 3-3. 연령 예외 처리

- 활동지원은 일부 65세 이상 이용자도 신청 가능한 예외가 존재
- `birth_year`만 저장하므로 실제 만 나이와 계산상 차이가 발생할 수 있음
- 기본 연령 기준을 벗어난 사용자가 예외적으로 신청 가능한 제도를 완전히 놓치지 않도록 처리 필요
- 연령 예외와 추가 자격은 `eligibility_summary`에서 안내

**개발팀 확인 필요:** 예외 대상 제도를 검색 결과에 별도로 노출할지, 기본 연령 조건을 완화할지 결정이 필요합니다.

### 3-4. JSON 구조

ERD v1.4의 `target_conditions`는 JSONB로 정의되어 있으나, 내부 필드명은 명세에 확정되어 있지 않습니다.

기획에서는 제도별 연령 기준과 예외 조건을 전달하며, JSON 키 구조는 백엔드 C와 협의하여 확정합니다.

## 4. 제도별 상세 안내 문구

`support_program` 테이블의 `summary`, `eligibility_summary`, `procedure`에 반영할 내용입니다.

### 4-1. 긴급돌봄

**`summary`**

보호자에게 갑작스러운 돌봄 공백이 발생했을 때 일시적인 돌봄을 지원하는 제도

**`eligibility_summary`**

6세 이상~65세 미만 등록 발달장애인 중 보호자의 치료·입원, 경조사, 심리적 소진 등으로 일시돌봄이 필요한 경우

**`procedure`**

지역발달장애인지원센터 신청 → 이용 대상 및 사유 확인 → 긴급돌봄 연계

### 4-2. 주간활동

**`summary`**

성인 발달장애인의 낮 시간 활동과 지역사회 참여를 지원하는 제도

**`eligibility_summary`**

18세 이상 등록 지적·자폐성 장애인 대상. 취업·다른 서비스 이용 및 시설 입소 여부 등에 따라 일부 제한 또는 예외 존재

**`procedure`**

주소지 행정복지센터 신청 → 자격 결정 → 지정 제공기관 이용

### 4-3. 활동지원

**`summary`**

장애인의 일상생활과 사회활동에 필요한 도움을 지원하는 제도

**`eligibility_summary`**

기본 6세 이상~65세 미만 등록 장애인 대상. 방문조사와 자격심의를 거쳐 지원 여부를 결정하며 일부 연령 예외 존재

**`procedure`**

주소지 행정복지센터 등 신청 → 방문조사 → 수급자격 심의 → 활동지원기관 이용

### 4-4. 가족휴식지원

**`summary`**

발달장애인 가족의 휴식과 여가활동을 지원하는 제도

**`eligibility_summary`**

발달장애인 및 가족 대상. 지역별 사업수행기관의 참여자 모집과 대상자 선정 절차에 따라 참여 가능

**`procedure`**

지역 사업수행기관 모집 확인 → 신청서 및 증빙서류 제출 → 대상자 선정 → 프로그램 참여

### 4-5. 부모상담지원

**`summary`**

발달장애인 부모와 보호자의 심리·정서적 부담 완화를 위한 상담지원 제도

**`eligibility_summary`**

등록 발달장애인 자녀의 부모·보호자 대상. 9세 미만 미등록 자녀에 대한 증빙서류 예외 존재

**`procedure`**

주소지 행정복지센터 또는 복지로 신청 → 자격 확인 → 상담기관 이용

## 5. 시설 데이터 활용 및 제도–시설 유형 매핑 정책

기존 #29·#30에서 합의한 공공데이터 적재 방식을 유지하고, 5개 지원제도와 관련 시설 유형을 연결합니다.

### 5-1. 기존 시설 데이터 활용 기준

| 항목 | 적용 기준 |
| --- | --- |
| 시설 데이터 | 기존 용인시 장애인복지시설 CSV 53건 |
| 데이터 출처 | `YONGIN_API` 42건 + `MANUAL` 11건 |
| 시설 유형 | CSV에 정의된 9개 `facility_type` |
| 신규 시설 추가 | 이번 MVP 범위에서 제외 |
| 단기거주시설 | 기존 DB 기준 0건 유지 |
| 시설 검색 결과 0건 | 해당 제도 및 공식 문의처 안내 |
| 제도·시설 모두 검색 결과 없음 | 빈 배열 반환 |

### 5-2. 제도–시설 유형 매핑 기준

기존 `program_facility_type` 구조를 활용하여, **지원제도의 목적과 시설 유형의 서비스 성격 간 관련성**을 기준으로 매핑합니다.

이번 매핑은 해당 제도의 공식 지정 제공기관을 확정하는 작업이 아니라, 돌봄바통에서 안내할 관련 지역 복지시설을 연결하기 위한 기획 기준입니다.

**매핑 원칙**

- 기존 CSV의 시설 유형 및 데이터 구조 유지
- 제도와 시설 유형의 서비스 목적 및 관련성을 기준으로 연결
- 특정 제도의 공식 지정 제공기관 여부와 관련 시설 여부를 구분
- 실제 사업 제공 여부가 확인되지 않은 시설을 공식 제공기관으로 표기하지 않음
- 매핑 시설은 '관련 시설'로 안내하고 실제 서비스 제공 여부는 기관 확인 필요
- 단기거주시설 0건 유지 및 임의 시설 추가 없음

### 5-3. 제도별 시설 유형 매핑표

| 제도 | `program_type` | 연결할 `facility_type` | 해당 시설 수 |
| --- | --- | --- | --- |
| 긴급돌봄 | `EMERGENCY_CARE` | 매핑 없음 | 0건 |
| 주간활동 | `DAY_ACTIVITY` | `주간이용센터` | 10건 |
| 활동지원 | `ACTIVITY_SUPPORT` | `자립생활지원센터(IL)` | 3건 |
| 활동지원 | `ACTIVITY_SUPPORT` | `장애인복지관` | 3건 |
| 가족휴식지원 | `FAMILY_REST` | `장애인복지관` | 3건 |
| 부모상담지원 | `PARENT_COUNSELING` | `장애인복지관` | 3건 |
| 부모상담지원 | `PARENT_COUNSELING` | `장애아재활치료시설` | 5건 |

**매핑 결과**

- 총 5개 지원제도 중 4개 제도에 관련 시설 유형 연결
- 실제 매핑 관계는 총 6개 행
- 활용 시설 유형은 총 4개
- 긴급돌봄은 기존 DB에 단기거주시설이 없어 매핑하지 않음
- 시설 수는 기존 CSV 기준이며 제도별 중복 매핑을 포함하므로 단순 합산 불가

위 매핑은 시설 유형의 관련성에 근거한 **MVP 기획 매핑안**입니다. 각 시설이 해당 지원제도의 공식 제공기관이라는 의미는 아닙니다.

### 5-4. 매핑 대상 선정 이유

| 제도 | 연결 시설 유형 | 선정 이유 |
| --- | --- | --- |
| 긴급돌봄 | 없음 | 기존 DB에 단기거주시설이 없으며, 일반 거주시설을 긴급돌봄 제공기관으로 간주하기 어려움 |
| 주간활동 | 주간이용센터 | 낮 시간 돌봄 및 일상 활동 지원이라는 서비스 목적의 관련성 |
| 활동지원 | 자립생활지원센터(IL), 장애인복지관 | 장애인의 자립생활과 일상생활 지원이라는 서비스 목적의 관련성 |
| 가족휴식지원 | 장애인복지관 | 장애인 가족 대상 지원 및 복지 프로그램과의 관련성 |
| 부모상담지원 | 장애인복지관, 장애아재활치료시설 | 장애인 가족 지원·상담 및 발달지원 서비스와의 관련성 |

**주의:** 위 선정 이유는 시설 유형에 대한 기획상 연결 근거이며, 개별 기관의 사업 수행 여부를 확인한 결과는 아닙니다.

### 5-5. 미매핑 시설 유형

| `facility_type` | 시설 수 | 미매핑 사유 |
| --- | --- | --- |
| 거주시설 | 11건 | 상시 거주 중심 시설로, 긴급돌봄 제공기관과 구분 |
| 공동생활가정 | 11건 | 공동 주거 및 생활 지원 중심 |
| 직업재활시설 | 8건 | 직업훈련·근로 지원 중심으로 기존 제도와 직접 대응 어려움 |
| 시각장애인등 생활지원센터 | 1건 | 기존 5개 제도와의 직접적 연계 기준 불명확 |
| 수어통역센터 | 1건 | 의사소통 지원 중심으로 기존 제도와 직접 대응 어려움 |
- 미매핑 시설은 총 32건
- 기존 DB에서 삭제하지 않으며, 지원제도 매핑에서만 제외
- 향후 실제 제공 사업이 확인될 경우 매핑 기준 재검토 가능

### 5-6. 매핑 구조 관련 주의사항

현재 `program_facility_type`은 개별 시설이 아닌 시설 유형 단위로 연결됩니다.

따라서 특정 유형 내 일부 시설만 해당 제도를 실제 운영하더라도, 동일 유형의 모든 시설이 관련 시설로 조회될 수 있습니다.

이에 따라 다음 기준을 적용합니다.

- 매핑된 시설을 '해당 제도 공식 제공기관'으로 표시하지 않음
- 제도 상세 정보와 관련 시설 정보의 의미를 구분
- 실제 서비스 제공 여부, 신청 가능 여부 및 이용 조건은 기관에 별도 확인 필요
- 시설별 지정 여부에 따른 정밀 매핑은 현재 MVP 구조의 한계로 구분

**개발팀 확인 필요:** 위 관련 시설 유형 매핑 정책이 기존 RES-02 응답 구조 및 시설 추천 문구에 적용 가능한지 검토 부탁드립니다.

## 6. 검색·상세 조회 정책 (RES-01·02)

### 6-1. 검색 조건

- `careTerm`: `SHORT` / `LONG` / 생략 가능
- `neededDate`: 돌봄이 필요한 날짜
- `district`: 대상자 등록 지역을 기본값으로 사용
- `dong`: 세부 지역
- `kind`: 제도 또는 시설 구분

제도는 연령과 돌봄 기간을 기준으로 1차 필터링하며, 관련 시설은 5장에서 정의한 매핑을 활용합니다.

### 6-2. 검색 결과 처리

| 상황 | 처리 |
| --- | --- |
| 조건에 맞는 제도 존재 | 제도 카드 반환 |
| 제도에 매핑된 시설 존재 | 관련 시설 카드 반환 |
| 관련 시설은 있으나 공식 제공 여부 미확인 | '관련 시설'로만 안내하고 기관 확인 문구 표시 |
| 매핑된 시설 0건 | 제도 정보만 반환 |
| 제도·시설 모두 없음 | 빈 배열 반환 |
| 실제 지원 자격 확인 불가 | 기관 확인 안내 문구 표시 |

**긴급돌봄 처리 예시**

- `EMERGENCY_CARE` 제도 정보는 정상 조회
- 기존 DB에 단기거주시설 0건이므로 매핑 시설은 반환하지 않음
- 제도 상세 정보에서 신청 절차 및 공식 문의 경로 안내
- 단기거주시설이 없는 것을 긴급돌봄제도 자체가 없는 것으로 처리하지 않음

검색 결과에는 기존 API 명세에 정의된 아래 문구를 공통 적용합니다.

> 실제 신청 자격과 이용 가능 여부는 해당 기관에 확인이 필요합니다.
> 

### 6-3. 관련 시설 표시 기준

시설 유형 매핑으로 조회된 기관은 **관련 시설**로 안내합니다.

- '신청 가능 기관', '지정 제공기관', '해당 제도 운영기관' 등의 확정적 표현 사용 금지
- 실제 제도 운영 여부는 해당 기관 및 공식 사업 담당 기관에 확인 필요
- 매핑 정보만으로 서비스 이용 가능 여부를 보장하지 않음

### 6-4. 필요 날짜 처리

`neededDate`는 사용자가 돌봄이 필요한 날짜를 입력하는 값이며, 시설의 실시간 예약 가능 여부나 잔여 정원을 확인하는 기능은 아닙니다.

사용자 요청 중 외부 공공데이터 API를 직접 호출하지 않고, 기존 DB에 적재된 정보를 기준으로 검색합니다.

## 7. 개발팀 추가 확인 요청

| 항목 | 확인 요청 |
| --- | --- |
| `target_conditions` | JSON 내부 필드명 및 연령 조건 표현 방식 |
| 연령 예외 | 활동지원 65세 이상 등 예외 대상 검색 노출 방식 |
| `birth_year` | 정확한 만 나이 정보가 없는 경우 연령 경계 처리 방식 |
| 시설 유형 매핑 | 5장의 관련 시설 기준 매핑안 적용 가능 여부 |
| 검색 응답 문구 | 매핑 시설을 '관련 시설'로 구분하여 표기할 수 있는지 |
| 유형 단위 매핑 한계 | 일부 시설만 지정기관인 경우에도 동일 유형 전체가 조회되는 문제 |
| `doc_version` | 공식 웹페이지를 근거로 사용할 때 버전 저장 기준 |
| 가족휴식지원 | 2026년 용인 지역 참여자 모집 및 신청 경로 확인 |

**우선 확인 요청 사항**

현재 시설 매핑 정책은 공식 제공기관 여부가 아닌 관련 시설 유형을 기준으로 정의했습니다.

기존 DB 구조를 유지한 상태에서 해당 정책으로 시드를 등록하고 RES-02에서 관련 시설로 안내하는 방식이 가능한지 확인 부탁드립니다.
