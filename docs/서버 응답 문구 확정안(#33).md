# 서버 응답 문구 확정안 (#33)

## 1. 무엇을

AI·API 명세 v1.4를 기준으로 소진 지원 화면(5.4), 위기 안전 안내 화면(5.5), 상담 연락처 및 자원 추천 이유 문구를 정리했습니다.

기존 API 응답 구조는 유지하며, 문구 생성이 필요한 부분은 LLM 대신 서버 고정 문구 및 템플릿을 사용합니다.

### 작업 내용

- 소진 지원 안내 문구 및 버튼 확정
- 위기 안전 안내 문구 및 버튼 확정
- 공식 상담·긴급 연락처 확인
- 지원제도·관련 시설 추천 이유 템플릿 확정
- 화면 표시 및 예외 처리 기준 정리

## 2. 소진 지원 안내 (5.4 / SUP-01)

### 2-1. 최종 안내 문구

> 요즘 기록에 지치신 날이 자주 보여요.
> 
> 
> 보호자가 쉴 수 있도록 돕는 제도가 있어요.
> 

### 2-2. 노출 조건

AI 명세 v1.4의 기존 소진 누적 판정 규칙 유지

- 최근 14일 이내 소진 신호 발생 날짜 3일 이상
- 최근 14일 내 동일 안내를 표시한 이력이 없는 경우
- 날짜 계산은 KST 기준
- 위기 신호는 소진 누적 계산에서 제외

### 2-3. 관련 지원제도

| 순서 | 지원제도 | `program_type` |
| --- | --- | --- |
| 1 | 발달장애인 부모상담지원 | `PARENT_COUNSELING` |
| 2 | 발달장애인 가족휴식지원 | `FAMILY_REST` |
| 3 | 발달장애인 긴급돌봄 | `EMERGENCY_CARE` |

지원제도는 기존 DB에 등록된 정보를 활용하며, 실제 자격 여부를 자동 확정하지 않습니다.

### 2-4. 버튼 및 이동

| 버튼 | 동작 |
| --- | --- |
| 지원제도 확인 | 관련 제도 상세 화면(5.3) 이동 |
| 나중에 확인 | 안내 화면 닫기 |

### 2-5. 주의사항

- 소진·번아웃·우울 등 진단으로 해석될 수 있는 표현 사용 금지
- 보호자의 상태에 대한 원인 추정 금지
- 위기 안내와 소진 안내를 혼용하지 않음
- 문구는 서버 고정값 사용, LLM 생성 금지

### 3-3. 후속 안내 문구

> 조금 진정된 뒤에는 발달장애인 부모상담 지원도 알아볼 수 있어요.
>

- 화면: 지원제도 상세(5.3)
- 긴급 연락처보다 낮은 우선순위로 표시

### 3-4. 버튼 및 이동

| 버튼 | 동작 |
| --- | --- |
| 109 전화하기 | 109 전화 연결 |
| 119 | 119 전화 연결 |
| 112 | 112 전화 연결 |
| 상담지원 확인 | 부모상담지원 상세(5.3) |

1577-0199는 상담 연락처로 화면에 노출하며, 전화 연결 버튼 추가 여부는 기존 UI와 협의합니다.

### 3-5. 주의사항

- 위기 안내는 일반 공감 문구나 AI 상담으로 대체하지 않음
- 자살·자해·타해 위험에 대한 진단 및 원인 해석 금지
- 위험 상황에서 긴급 연락처를 우선 노출
- 위기 판정은 AI 명세의 기존 서버 판정 규칙 유지
- 위기 대응 문구는 LLM이 아닌 서버 고정값 사용
- 오늘 기록은 기존 저장 정책에 따라 유지

## 4. 추천 이유 문구 (RES-02 / AI-04 MVP)

### 4-1. 적용 기준

MVP에서는 AI가 추천 이유를 생성하지 않고, 서버 템플릿을 사용합니다.

현재 제도–시설 유형 매핑은 공식 제공기관 지정 여부가 아닌 **관련 시설 유형 안내 기준**이므로, 실제 이용 가능 여부를 확정하는 표현은 사용하지 않습니다.

### 4-2. 제도 추천 문구

| 조건 | `reasonText` |
| --- | --- |
| `careTerm=SHORT` | 단기 돌봄과 관련된 제도예요. |
| `careTerm=LONG` | 장기 돌봄과 관련된 제도예요. |

### 4-3. 시설 추천 문구

**기본 템플릿**

`{구}에 있는 {시설 유형}이에요.`

| 예시 조건 | `reasonText` |
| --- | --- |
| 수지구 / 주간이용센터 | 수지구에 있는 주간이용센터예요. |
| 기흥구 / 장애인복지관 | 기흥구에 있는 장애인복지관이에요. |
| 처인구 / 자립생활지원센터(IL) | 처인구에 있는 자립생활지원센터예요. |

시설 유형 표시명은 기존 DB 유형을 기준으로 하되, 이용자에게 보여주는 명칭은 화면에서 자연스럽게 표현할 수 있습니다.

### 4-4. 금지 표현

다음과 같이 실제 자격이나 이용 가능성을 보장하는 표현은 사용하지 않습니다.

- 바로 이용할 수 있어요.
- 신청하면 선정돼요.
- 현재 이용 가능한 시설이에요.
- 해당 제도의 공식 제공기관이에요. (실제 지정 여부 미확인 시)

### 4-5. 공통 안내 문구

> 실제 신청 자격과 이용 가능 여부는 해당 기관에 확인이 필요합니다.
> 

검색 결과 및 관련 시설 안내 시 기존 API의 `disclaimer`를 유지합니다.

## 5. API 적용 기준

| API | 화면 | 적용 내용 |
| --- | --- | --- |
| `SUP-01` | 5.4 | 소진 안내 문구 2개 + 관련 제도 3개 |
| `SUP-02` | 5.5 | 위기 안내 문구 2개 + 연락처 4개 + 부모상담지원 |
| `RES-02` | 5.2 | 제도·시설 추천 이유 및 공통 안내 문구 |
| `RES-01` | 5.3 | 제도·시설 상세 정보 및 신청 안내 |
- 기존 API 필드 및 응답 형식 유지
- 소진·위기 안내 문구는 코드 상수로 관리
- 추천 이유는 규칙 기반 템플릿으로 처리
- LLM 생성 및 상담 기능 추가 없음

## 7. 개발팀 전달 및 구현 참고사항

| 항목 | 적용 기준 |
| --- | --- |
| 5.4 진입 | 기존 소진 감지 조건 유지, 5.0 직접 진입 시 SUP-01 동일 응답 사용 |
